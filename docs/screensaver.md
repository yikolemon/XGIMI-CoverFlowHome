# 本地视频屏保：需求、设计与验证

## 1. 使用目标与默认约定

用于投影仪睡前长时间播放本地视频。这是应用内屏保，不是 Android 系统 DreamService，不修改默认桌面、系统休眠策略或系统音量。

用户未指定的细节，初版作以下约定：

- **自动启动**：桌面连续无操作 10 分钟。可在设置中选关闭、1、5、10、15、30、60 分钟。键盘/遥控器/触摸操作重新计时；壁纸自动轮换不重置计时。
- **计时范围**：只在桌面可见、有窗口焦点、没有打开应用库时计时。离开桌面、打开设置或系统弹窗时取消；返回桌面后重新计时。
- **手动启动**：焦点先进入右上角按钮，再在 2 秒内独立按三次“上”。现有按钮短按打开应用库，长按打开壁纸设置；本版复用该入口，不改变原功能。进入按钮的那次上键不计数，长按产生的重复事件不计数，其他按键或失去焦点取消组合。
- **视频来源**：选择一个文件夹，持久保存只读授权，直接播放原视频，不复制。只读取本层目录，最多播放按名称排序的 20 条。默认有声，可在屏保选片浮层及设置中调节 0%–100% 音量并持久化记忆；保留已保存的个人选择。
- **播放**：记住上次选择，单个视频循环播放；按比例显示，允许黑边。推荐 1080p H.264/AAC MP4，具体解码能力取决于电视/投影仪。
- **选片**：播放时按“下”才创建底部横向封面条与下方音量控制条；黑色渐隐替代灰色矩形底板，封面悬浮排列，焦点略放大并显示细亮边框，正在播放项单独标记。上方显示当前选择名称与操作提示；左右移动、确定切换并收起，确认正在播放项不重播。在视频行再按下键可调节屏保音量（0%–100%，10% 步进，切换视频/退出重启均保持记忆）；上键返回或收起，8 秒无操作自动收起。
- **退出**：600 毫秒内两次独立返回键。若选片浮层打开，按返回键仅收起浮层并重置退出计时；浮层收起时首次返回显示提示，再次返回才退出。Home、关屏、切到后台也停止并释放播放器。

## 2. 资源边界

- 桌面不创建 MediaPlayer、SurfaceView、视频封面缓存或视频工作线程，只持有一个可取消的延迟回调和少量设置/按键状态；未配置视频时不排空闲定时任务。
- 播放使用独立的非导出 Activity、原生 MediaPlayer 和 SurfaceView，不添加播放器依赖，不运行 Service、轮询或后台播放。
- 从桌面进入屏保后释放桌面壁纸和卡片缓存；返回时使用已有后台加载逻辑恢复。
- 只有按“下”时提取可见视频的缩略图，输出目标 240×135，缓存最多 6 张，后台队列有上限。收起选片条后清理缩略图引用/排队任务。
- API 26 不使用可能解码整张 4K 帧的缩略图兜底，显示带名称的占位卡；API 27+ 使用缩放帧接口。
- onPause / Surface 销毁 / 退出都会释放 MediaPlayer；Activity 销毁会取消回调、关闭缩略图线程并释放缓存。只在屏保前台保持屏幕点亮。

## 3. 文件与失败处理

- 系统入口使用 `ACTION_OPEN_DOCUMENT_TREE` 和持久只读授权；绑定前后台验证目录及视频，失败保留旧绑定。不申请管理所有文件权限。
- 无可用系统目录选择器的电视使用媒体库文件夹列表，需要视频读取权限（Android 13+ 为 `READ_MEDIA_VIDEO`）；只列出媒体库已索引的视频所在文件夹，不冒充任意文件系统浏览器。USB/未索引目录需要系统提供目录授权。
- 备用应用目录：`/sdcard/Android/data/com.gathin.tvhome/files/screensaver/`，可通过文件管理器/ADB 放入视频后选择。兼容旧版导入文件；绑定新目录、取消绑定均不删除任何原文件或旧导入文件。
- 不再限制单个视频 512 MiB 或复制总量 2 GiB，因为不复制视频。SAF 枚举最多 1000 个目录项，媒体库查询最多 5000 项；过大媒体库提示改用系统目录选择器。
- 移动、删除文件、拔出设备或撤销权限后不保证可播放；设置显示不可用提示，重新授权/刷新可恢复。取消绑定会清空缓存数量，桌面不再自动启动屏保。
- 不支持的编码/缺失文件尝试下一条，每条最多尝试一次；全失败时停在黑色错误页，仍可选片或双击返回，不无限重试。
- 没有视频时自动启动不弹窗、不进入空屏保；手动启动引导去设置。
- 声音默认开启，支持 0%–100% 音量调节。有声时申请音频焦点；失去焦点不允许继续抢播。

## 4. 初版不包含

网络视频、下载、云同步、系统屏保注册、自动关机/睡眠定时、亮度或投影仪风扇控制、后台音频、任意公共目录扫描。

## 5. 验证清单

- 规则单测：三次上键时间窗/重置、双击返回边界、空闲时间、媒体扩展名、选片边界/整数溢出、确认当前播放项不重播与失败后可重试。
- 构建：release 单测与 APK；完整 Lint 的历史 TV banner 缺失需与新增问题区分。
- 真机：焦点三次上、按住不误触、桌面计时与系统弹窗/应用库互斥、视频循环和快速切换、静音/音频焦点、单次/双次返回、坏视频、Surface 重建、Home/关屏退出、反复进入退出内存。
- 不把 JVM 单测当成播放器/硬解码/长时间稳定性验证，不宣称未测量的“零内存”或启动速度提升。

## 6. 提交边界

冷启动优化为已推送的独立提交 `3cc41a1`。本屏保需求完成后单独本地提交，**不推送**。

## 7. 实现与二次自查

- `ScreensaverRules`：纯 Java 的组合键、双击、空闲时间、格式和选片规则；`ScreensaverRulesTest` 覆盖 12 个用例。
- `CoverFlowHome` / `MainActivity`：输入与窗口焦点驱动单次空闲回调；应用库打开时取消，返回桌面重新计时。右上角按钮保留短按/长按行为。
- `ScreensaverStore` / `ScreensaverFolders` / `ScreensaverVideo`：统一 URI 媒体引用，支持 SAF、媒体库文件夹和应用目录；绑定/解绑串行互斥，持久化成功才释放旧目录授权；处理 SharedPreferences.commit 失败的内存回滚。
- `ScreensaverActivity`：Surface 和 Activity 生命周期共同约束播放；15 秒准备超时；旧播放器回调/切换任务有身份或代际检查。无视频的自动请求更新计数后直接退出，不留空白屏保。
- `ScreensaverChooser`：缩放封面只按可见范围生成；一个屏保 Activity 复用一个封面线程，收起时清队列，过期结果不进入缓存，避免反复按下开关时叠加解码线程。
- `ScreensaverSettingsActivity`：目录验证、枚举均放后台；显示目录名称和数量，提供文件夹选择、屏保音量、空闲时长、刷新、取消绑定入口。
- 桌面完全进入后台时清理海报与壁纸引用，包含“设置 → 预览”路径。清理后禁止后台元数据回调重新生成海报，恢复桌面再按可见范围重建。
- 默认有声，播放时申请音频焦点；音量调至 0% 后不申请音频焦点。有声播放处理暂失焦点（包括视频尚未准备好的情况）、永久失焦和恢复。全部视频失败时归还音频焦点。

## 8. 验证结果与剩余风险

- 本轮新增规则测试 12 项；全量 48 项 JVM 单测通过，Release APK 构建通过。
- 完整 Lint：原有 `MissingTvBanner` 错误仍在；当前 25 项警告，含 Android 14 部分媒体访问适配提醒、字符串复数建议等；未添加 baseline 或关闭检查。
- 已在 Android TV API 36 模拟器验证三次上启动、两条本地测试片循环与封面、左右切换、双返回退出；此前验证 1 分钟空闲自动启动，随后恢复 10 分钟。
- 文件夹与视觉改版后重新通过 48 项 JVM 单测及 Release 构建，覆盖安装；截图确认悬浮封面/渐隐样式，媒体库 `Movies/ScreensaverDemo/` 绑定后直接播放并提取封面成功，取消绑定操作后原视频仍存在。测试素材为自行生成的短视频，不加入仓库。
- 模拟器系统目录选择器是占位程序，因此未验证真实 SAF 授权、重启授权保留、USB 拔插。没有投影仪真机，硬解码、音频焦点、整夜稳定性与 CPU/内存仍待验证。测试片没有音轨，不能据此证明有声输出正常。
- Android 14 部分媒体访问可能只显示部分视频；目录授权入口不受媒体库部分授权限制，权限变化后应重新选择/授权并刷新。扩展名可识别不代表设备一定能解码。
- 清理图片引用/关闭播放器不等于 Android 进程内存会立刻降到零；GC、渲染线程和系统解码器的资源回收时机仍由系统决定。
- 本版是应用内屏保，不阻止系统强制休眠/关机，也不能接管其他应用的空闲行为。

### 真机验收建议

1. 设置 1 分钟自动屏保，确认输入会重计时；应用库、壁纸设置、系统弹窗和其他应用前台时不启动。
2. 选择含两个可播放 MP4 和一个损坏文件的文件夹，验证循环、封面、快速切换、当前项确认不重播、错误跳过；全部损坏时仍可双击返回。验证重启后目录授权、空目录、撤销权限、USB 拔插和取消绑定不删除原文件。
3. 确认进入按钮的上键不算三次，按住上不触发；其他键/焦点变化会清空组合。单次返回不退出，600 毫秒内第二次返回才退出。
4. 静音与有声分别测试 Home、关屏、切换其他应用、音频焦点暂失/恢复；返回桌面后壁纸和应用海报应恢复。
5. 连续进入退出 20 次，再进行整夜循环，使用 `adb shell dumpsys meminfo com.gathin.tvhome` 和设备日志观察资源是否持续增长、是否存在解码器错误或异常后台播放。
